## 1. 结论

- 候选 **157 条**（主集 137 / 边界集 20），按「用户以后会去哪里找它、跨类按主要用途归类」逐条重判。
- 处置 **10 条**：**改标 3**、**移入边界集 7**；其余 147 条维持 v1 标注。

- 12 个正常 L2 仍全部覆盖；不得不在边界集反映的缺口主题：**学习资源类、安全类**（12 个 L2 无对应节点，属 #18 升格流程，不在本票范围）。
- 校验器：**结构校验 0 错误**；12 条错误全部是「总量 / 分层 / 媒体形态」配额缺口（v1 已有 8 条同类缺口，v2 在其之上新增总量/visible/blind/ops_infra 4 条）。
- **v2 与 v1 的指标不可直接比较**（#14 §3.6）：分母、组成都变了。

## 2. 复核口径

判定规则（沿用 #20 标注口径与 #19 V-C4 prompt 的判定方法）：

1. 以「用户以后会去哪里找它」为准；跨类时按主要用途归类。
2. 媒体形态与载体类型（工具 / Skill / 视频 / 合集）不是分类依据，看内容面向的生产领域。
3. Skill / 工具类条目：内含领域方法或框架 → 按领域归类；纯工具用法、能力说明 → `l1_tech/l2_prompt_agent`。
4. 内容不属于 12 个正常 L2 → 移入边界集（#14 §3.5 / #18 弃权语义）；不把「最近邻」硬塞进主集。
5. 同一 L1 内的 L2 分歧不因模型判错而改标（那属于 prompt/模型能力信号，不是跨类金标错误）。

候选来源（去重后 157 条）：

- v1 基线（#21）可见集 **59 条错例与弃权**（模型与金标 L1/L2 分歧）——用分歧定位「值得重判」的样本，但**不以模型答案为准**；
- 三类模式关键词扫描：技术项目 vs 商业观察、工具合集 vs 内容创作、学习资源 vs 知识管理；
- Skill / 技能载体扫描（70 条）：核对「载体 vs 主题」口径是否自洽；
- 边界集 51 条同口径扫描（命中 20 条）：边界集金标只作最近邻、不参与门线，本次**未调整**。

## 3. 三类模式处置

### 3.1 技术项目 vs 商业观察（候选 22 → 改标 1）

- **改标 1 条**（v1 主集 #32，即 #19 原型暴露的 T9）：开源的全球实时情报仪表盘项目介绍。v1 金标 `l1_biz/l2_insight` → `l1_tech/l2_ops_infra`。正文主体是技术选型（地图引擎、图层）、本地模型（Ollama）部署与自托管能力；「情报 / 金融」是产品主题，不是行业研报。模型一致判 tech **不是跑偏**，是 v1 把「商业叙事」当成了分类依据。
- **维持 21 条**：公司计划/融资/收入里程碑/访谈/独立开发复盘/行业案例等确实属行业观察（OpenAI 开源计划、Manus 收入纪录、独立开发营收复盘、Lex Fridman 访谈、快手 AI 研发范式复盘等）；「OSS 投资记分卡 skill」这类**内含投资判断方法**的条目保留在 `l1_biz`。

### 3.2 工具/技能 vs 内容创作（候选 39 + Skill 载体 70 → 改标 2）

- **改标 2 条**（v1 主集 #72、#73）：两个 Skill 的**内容主体**是「主次矛盾决策分析」与「行业专家报告（价值链 / 竞争结构 / 行业生命周期）」，属商业认知方法，不是提示工程。按第 3 条口径改为 `l1_biz/l2_insight`，与同类「OSS 投资记分卡 skill」（#183，维持 biz/insight）对齐。
- **维持**：设计 / 视频 / 写作 / 运营类工具与 Skill 按「内容面向的生产领域」保留在 `l1_content`（与 #19 few-shot 的「视频脚本 Skill → 视频与音频」一致）；纯 Agent / Skill 用法、能力说明类保留 `l1_tech/l2_prompt_agent`；工具合集按领域归（视频工具→视频、免费字体→图像、提示词平台→提示工程）。

### 3.3 学习资源 vs 知识管理（候选 21 → 移边界 7）

- **移边界 7 条**：#9（盲测）、#77、#89、#124 原标 `l1_productivity/l2_km`；#93、#113、#114 原标 `l1_tech/l2_ops_infra`。共同点：主题是**学习资料 / 学习路径**（课程链接合集、AI 博客清单、备考卡片、网络安全路线图、安全职业路径、物联网安全资源合集、背单词应用），12 个 L2 无对应节点，v1 借 km / ops_infra 兜底。按 #14 §3.5 与 #18 弃权语义，这类条目应进边界集观察弃权/建议，不参与门线。
- **维持**：阅读 / 记忆方法、笔记与知识库搭建、阅读辅助工具仍在 `l2_km`（记忆方法文章、Obsidian 知识库、论文阅读辅助、笔记整理 Skill 等）——它们管的是「信息怎么管」，不是「学什么」。

## 6. 校验结果与已知缺口

`node scripts/eval/validate-eval-set.mjs --file .local/eval/sets/2026-10-v2.jsonl --boundary .local/eval/sets/2026-10-v2.boundary.jsonl`

- 结构校验（字段、枚举、父子关系、标签数量/长度、entry_id 唯一、版本单一）：**全部通过**。
- 退出码 1，错误 12 条，全部为配额类：总量 193≠200、visible 144≠150、blind 49≠50；L1 productivity 23、L1 biz 14（<40）；L2 social_media 8、automation 4、personal_ops 1、ops_infra 9、biz_model 6、insight 8（<10）；视频占比 13.5%（<20%）。
- 这些缺口在 v1 已存在 8 条（productivity / biz / social_media / automation / personal_ops / biz_model / insight / 视频）；v2 在此之上新增 4 条（总量、visible、blind、ops_infra 9<10），其余缺口数值随移出样本变小。根因是收藏样本分布本身不满足 #14 §3.1 的全部分层，**未用公开内容或编造条目补齐**（沿用 #20 的处理）。
- 未覆盖节点变化：12 个正常 L2 仍全覆盖；本次新增的边界样本集中在「学习资源 / 安全」两类**无节点主题**，属 #18 的升格议题，不在本票范围。

## 7. 对 #23 的交接

- 基线改绑 **`2026-10-v2`**；v1 基线报告与 `baseline-index` 保留不动（#14 §4.4）。
- v2 可见集为 **144 条**（不是 150），报告会出现 composition warnings，照实记录。
- v2 与 v1 **不计算差值**（#14 §3.6）；本次移出的 7 条中，6 条可见样本（3 条模型原本判对、3 条判错）不再进分母，另有 3 条改标（2 条由错转对、1 条 L1 由错转对），因此 v2 读数相对 v1 的变化**不能解读为 prompt 或模型变好/变坏**。
- 剩余未处理项（本票边界外，见 §8）不影响本次基线定义，但复跑时若出现新的跨类错例，仍按本报告口径补票。

## 8. 本票边界外、明确未处理

- **同一 L1 内的 L2 噪声**：不改。典型如金标 `l2_ops_infra` 的 L1 准确率 72.7%（8/11）、L2 准确率 18.2%（2/11）——多为安全类工具/资讯与「部署与环境」的 L2 混淆；这属于 prompt 与模型能力信号，改金标会让评测集更像为模型定制。
- **工具型条目的兜底归类**：PDF 工具箱、浏览器插件、AI 浏览器等落在 `l2_km` / `l2_automation` 的条目未改（不属三类跨类模式）。
- **分类树缺口**：学习资源、安全类是否需要新 L2，走 #18 升格流程，本票不改树（taxonomy 1.1.0 冻结）。
