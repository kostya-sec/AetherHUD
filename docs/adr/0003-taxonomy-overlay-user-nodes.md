# 分类树采用只读底表 + 用户覆盖层

分类树随安装包分发（macOS 在 `.app` 内、Windows 在安装目录），应用内无法安全写回：改包内文件会破坏签名，升级会覆盖。但升格（#18）需要把用户新建的 L2 持久化。因此 `taxonomy.json` 保持**只读底表**，用户新增节点写入 `app_data_dir/taxonomy.overlay.json`（覆盖层），启动时合并为**生效分类树**，生效版本形如 `1.1.0+u3`；自建节点 id 以 `l2u_` 开头，与官方 id 永不冲突。

## 备选方案

- **首次安装复制一份可写 `taxonomy.json`，此后只读写它**：被否——官方每次升级都要与用户改过的文件做三方合并，冲突处理成本高且容易丢用户数据。
- **自建节点存 SQLite 表**：被否——违反 ADR-0001「taxonomy.json 为分类唯一真源」，且启动时要合并两份真源。
- **应用内不允许新增节点，只手工改文件后重启**：被否——最终用户做不到（安装目录不可写）。

## 后果

- 任何读分类的地方都必须先合并底表与覆盖层：分类器 prompt 注入、HUD 导航、评测 CLI、评测集校验脚本都不例外；应用启动与升格后导出 `taxonomy.effective.json` 供外部工具读取。
- 官方升级新增节点与自建节点撞名时按「官方优先、自动并入」处理，覆盖层保留 `merged_into` 映射。
- 覆盖层随数据库一起备份（`backups/taxonomy.overlay.<ts>.json`）。
