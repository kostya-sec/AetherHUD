# FTS5 用 trigram + LIKE 兜底，正文只索引前 500 字符

## 背景
中文全文搜索在 SQLite FTS5 上必须解决分词；同时 trigram 索引体积约为被索引文本的 4.6 倍（实测 10k 条 / 3.86 MB 中文语料），条目正文长度直接决定库体积。

## 决策
- 分词用 **trigram**（零扩展、零 C++ 工具链、跨平台无打包风险），`< 3` 字符查询走 `LIKE` 兜底（10k 级 3–6 ms）。
- FTS 只索引 `excerpt`（正文前 500 字符）+ 标题/笔记/作者；`body_md` 存 1500 字符供分类与本地留存，但不全量进索引。1 万条目库体积约 100–130 MB。
- 查询侧把用户输入切段加引号拼 `AND`，不直接把原始输入塞进 `MATCH ?`。

## 备选方案
- wangfenjin/simple（jieba + 拼音）：功能最强，但引入 C++14 工具链、arm64 macOS 必须上 macOS 构建、jieba 首查 ~4 s 需预热；为 PRD 未要求的拼音/1 字搜索付出过高打包与冷启动成本。
- jieba-rs 应用层预分词：体积更小（~1.9×）且全文可搜，但要求写入/查询同词典版本，词典升级即全量重建，且中文歧义会产生召回断层。
- 全文进 trigram：1 万条目 260 MB+，2 万条目将逼近 800 MB，可逆性差。

## 后果
搜索覆盖以「标题 + 正文开头」为主，深处正文搜不到；索引长度是 Rust 常量（`FTS_EXCERPT_CHARS`），升级路径 = 改常量 + 重建 FTS（`rebuild_fts()`）。`3 字下限` 与空格语义成为前端查询路由必须处理的规则。
