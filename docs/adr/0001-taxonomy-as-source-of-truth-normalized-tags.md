# 数据模型以 taxonomy 为外部真源、标签为规范化三表

## 背景
条目同时要满足「刚性 L1/L2 层级」与「动态演进的 L3 标签」两类筛选，且 AGENTS.md 要求按 l1/l2/tags 过滤必须走索引。

## 决策
`entries` 只存 `l1_id/l2_id`（不冗余显示名），taxonomy.json 保持唯一真源、运行时载入内存；L3 标签落地为 `tags` + `tag_aliases` + `entry_tags` 三张规范化表，标签使用计数**不物化**（查询时按 active 条目聚合）。

## 备选方案
- 冗余存 l1_name / format_tag_name（demo 做法）：被否——taxonomy 演进时必然不一致。
- L3 标签存 JSON 列：被否——标签是全局唯一实体（#9），且 AND 过滤要索引。
- 计数列/升降级事件：被否——#9 明确无状态规则，物化状态会与「查询时计算」的语义冲突。

## 后果
显示名变更不触达数据行；但任何读取条目分类的界面都必须先加载 taxonomy 内存。标签改名零成本（引用 id），代价是 FTS 不能索引标签名，标签搜索改走独立查询路径。
